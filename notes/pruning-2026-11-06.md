# Fact-check and prune, 2026-11-06

*Corpus: 422 nodes / 1023 edges → 351 nodes / 865 edges. The pre-prune source is
in `archive/pre-prune-2026-11-06/`; nothing was deleted without a copy.*

**Why.** The corpus now serves one purpose: design input for a 2026 successor to
HyperCard/HyperTalk. Historical research is not the goal, so history nodes survive
only where a design argument leans on them. Before this pass nothing had been
checked against primary sources, and the first spot checks found errors in the
load-bearing layer (the object model and language reference), not just in the
history.

**Method.** Prune by design relevance first (no research spent on what was going to
be dropped), then check what remained, layer by layer, against primary sources.
Four read-only subagents each took one layer and returned findings with a URL and a
verbatim quote. Findings that changed a design argument, or where two reports
disagreed, were re-checked directly against Wikipedia's wikitext, two TidBITS
articles and a MacTech item. All corrections were applied by scripted exact-match
edits (an edit that did not match aborted the run), loaded into a throwaway
SurrealDB, and checked for isolated nodes, dangling endpoints and duplicate edges
before the live files were replaced.

## 2. Errors fixed that matter to a design

These were stated as fact in the corpus and are false (Apple guide unless noted).

- **Unhandled messages are not all silent.** System messages like `mouseUp` are
  dropped; a command or user message that nothing handles raises *"Can't
  understand X"*. The old text said any unhandled message vanishes.
- **Message path:** handlers are tried first at each level, then that level's
  XCMDs/XFCNs; HyperCard checks externals *before* its built-ins; the OS is not on
  the path; where a message starts depends on its kind. The corpus put XCMDs and
  the OS last.
- **Scheduling:** `do "…" in 3 seconds` is not HyperTalk. The 2.0/2.1 guide has no
  timer command, only `wait` and `on idle`. (`send … in time` is documented for
  LiveCode; whether late HyperCard versions had it is **unconfirmed**.)
- **`it` is local**, not global. Variables are local unless declared `global`.
- **Tools:** 18, not seven; Button and Field tools place parts (the pencil is a
  paint tool).
- **Home stack:** a mandatory ordinary stack (Home card, preferences, a script and
  externals in every stack's path), not the source of menus and palettes.
- **Message box:** a floating one-line window (Cmd-M), not a strip at the bottom
  of every window; only `do`/`if`/`send` work in it.
- **Card size:** variable from 2.0 (64–1280 px, one size per stack), not fixed at
  512×342. Windows have properties but are not objects.
- **Marking:** the boolean card property is `marked` (`mark`, `unmark`); there is
  no `marks`. `find` does not mark. "Browse as thumbnails" was wrong: that is
  Recent (last 42 cards).
- **Clickable text:** `linkText`/`linkParts` do not exist; 2.0 added *group* text
  read with `clickChunk`/`clickText`.
- **Containers** are fields, variables, the selection and the message box only.
  Buttons, menus and files are not containers.
- **Reference details:** five user levels (not four); `family` is a radio-button
  group, not a font; `errorDialog`, not `doError`; `itemDelimiter` arrived in 2.1;
  `annuity`/`compound` take two arguments; `the sqrt of 4+12` is 14.
- **History that a design argument used:** the Player split is September 1992
  (Apple's run-only "HyperCard 2.1 Player", as its Claris licence expired), not
  2.2; HyperCard 2.2 is about late 1993 (contemporary press), though Wikipedia says
  1992. QTi is *QuickTime Interactive*; Calhoun, not Crow, showed the 1996 alpha.
  SK8 was Apple ATG's (Kleiman), not Atkinson's. Oracle Card was a redistributed
  clone engine, not an XCMD. The Wired piece is Leander Kahney's article of 14 Aug
  2002, not an interview, and the quote is "*might* have been the first Web
  browser". Wasm is sandboxed, so it is not "XCMD-shaped trust". Dynamicland's
  Oakland space has been closed since Covid.

## 3. Second pass: Apple's own HyperCard 2.2 guide

The first pass could only reach a third-party 1994 help stack for the keyword layer.
The PDF already cited as `s_hc_script_guide` turned out to be Apple's **HyperCard
2.2** Script Language Guide with a usable text layer (about 30,000 lines, including
a categorized index of every command, function, property and system message). Every
keyword node was compared against that index for word, category and one-line
description.

- **Result:** 146 of the original keywords were present in the guide's text. Category
  agreed except for `do`/`exit`/`send` (Apple calls them keywords) and `version`
  (listed as a property). 148 of the 149 surviving keyword nodes are now
  `confidence = high`; `and`/`or` is `medium` because the guide is silent on
  short-circuiting.
- **Removed:** `text` and `formattedText` (not in the 2.2 guide); `comma` and `colon`
  as constants (Apple's constants are down, empty, false, formFeed, lineFeed, pi,
  quote, space, tab, true, up, zero..ten).
- **Corrected, and they matter:**
  - `within` sits at precedence level 2 with `not` and `there is a`, not with the
    comparisons at level 7. The corpus and the third-party help stack were both
    wrong; Apple's table 7-2 is clean in this copy.
  - A handler named like a HyperTalk command intercepts it, and functions can be
    redefined the same way ("A handler can intercept a HyperTalk command").
    `send … in <time>` does not appear anywhere in the guide.
  - `is a` also accepts `empty`; `enable`/`disable` apply to buttons, menus and menu
    items; `suspend` fires only when another application is launched with `open`;
    `quit` fires from the File menu or Command-Q; `exitField` is sent when a field
    is closed without changes (`closeField` only when text changed).
  - `and`/`or`: not specified. `lockMessages`/`lockRecent` do reset at idle time, as
    the corpus said.
- **Two of my own first-pass edits were wrong, and Apple's text overturned them.**
  I had weakened `go` from "trappable" to "unconfirmed" and rewritten
  `mouseDoubleClick` as "does not replace the first click's messages", both on the
  help stack's word. Apple says commands are messages that handlers can intercept,
  and that when `mouseDoubleClick` is sent it is "the only system message sent as a
  result of the second click". Both are restored.

## 4. Where my own first read was wrong (other)

- I distrusted "HyperCard 2.0 added a compiler" and "Atkinson's 2017 iBooks Author
  remark". Both are supported (Wikipedia; the quote is attributed to an April 2017
  video). The hedge was removed.
- The second subagent report was right about `within`; the keyword subagent, using
  the help stack, was wrong. Left-to-right association with `^` right to left is
  Apple's; the help stack said otherwise.
